# 架构与数据流

本文是接口与工作流设计草案，命名可随模块整理调整。当前公开实现范围见 [开放清单](roadmap.md)。

## 为什么按任务拆分

不同视频需要关注不同的信息。卡点混剪需要音乐段落、节拍与动作落点；故事视频需要事件、角色关系与旁白顺序。把这些任务拆成工具，有利于保留分析结果、检查中间产物，并在局部修改时复用已有结果。

这是架构选择的目的，效果需要在对应模块开放后用实际项目评估。

## 四层组织

| 层级 | 职责 | 位置 |
| --- | --- | --- |
| 应用层 | 接收用户输入，展示任务进展和产物 | `apps/` |
| 编排层 | 组合阶段、保存任务状态、路由剪辑路线 | `agent.py`、`pipeline.py` |
| 领域层 | 热点、素材、参考、需求、音频、剪辑、输出 | `modules/` |
| 工具层 | 单一分析或操作任务，返回可检查结果 | 各模块 `tools.py` 及预留工具文件 |

## 三种入口

1. **从选题开始：** 热点发现 → 用户选择或约束选题 → 素材收集 → 素材理解。
2. **从主题开始：** 给定主题 → 素材收集 → 素材理解；不调用热点模块。
3. **从素材开始：** 用户提供素材 → 素材理解；不调用热点发现或在线检索。

参考视频可以作为独立输入，不默认混入可剪辑素材。素材集合与参考集合均可为空或按需求调整，但进入实际剪辑前必须有可用素材。

## 核心数据契约草案

| 数据 | 主要字段 | 生产方 → 使用方 |
| --- | --- | --- |
| TopicBrief | 主题、时间范围、来源链接、讨论摘要 | trends → media / intent |
| AssetManifest | 素材 ID、路径、来源、许可、时长、技术信息 | media → learning / render |
| ReferenceNotes | 参考 ID、时间区间、镜头长度、节奏与转场观察 | learning → editing |
| CreativeBrief | 路线、主题、角色、时长、画幅、音乐、约束 | intent → audio / editing |
| AudioMap | 段落、节拍候选、底鼓候选、能量、置信度 | audio → editing |
| EditPlan | 素材 ID、入出点、时间线位置、音轨、转场 | editing → render |
| RenderReport | 输出路径、媒体参数、缺失项、检查结果 | render → 应用层 / 用户 |

上述名称为接口草案，不代表已经发布的 Python 类。素材 ID 与时间码应贯穿各阶段，便于追溯。

## 路线选择

- `beat`：先分析 BGM 的结构，再把镜头、动作与关键音乐位置对齐。
- `story`：先组织事件与叙事，再安排镜头、旁白和音乐。
- 热点发现独立于路线；两个方向都可直接使用用户素材。

## 工具选择原则

Agent 根据创作需求和已有分析结果选择工具，不要求每个项目运行所有工具。频段能量、乐器识别与音源分离是不同任务，不能互相替代。工具结果保留时间码、方法与置信度，避免把推断当作确定事实。

## 中间产物与输出

工作目录建议按项目保存输入清单、分析索引、参考笔记、剪辑计划和导出报告。原始素材及生成产物默认不进入 Git。

输出边界包括可检查的剪辑计划、剪辑工程适配与视频文件；具体支持的编辑器、渲染器及调用方式随适配器发布再列出。
